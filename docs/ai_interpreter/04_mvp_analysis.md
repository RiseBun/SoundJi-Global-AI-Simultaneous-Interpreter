# AI 同声传译助手 MVP 分析

版本：v0.2

本文档回答：72 小时内先做哪条最小闭环，哪些能力必须做，哪些能力应该放弃，如何证明 MVP 成立。

## 1. MVP 一句话

为个人学习者提供一个可上传英文技术课程音频或模拟流的工作台，自动生成中文双语时间轴、术语命中记录和会后复盘 Markdown/JSON。

## 2. MVP 用户和场景

| 项 | 决策 |
|---|---|
| 用户 | 正在学习英文技术课程的中文学习者。 |
| 场景 | 看英文公开课、技术分享、会议培训回放。 |
| 输入 | 3-5 分钟英文音频或模拟音频流。 |
| 输出 | 双语时间轴、术语命中、Markdown/JSON 导出。 |
| 核心价值 | 不只是听懂当下，还能会前控术语、会中看稳定状态、会后复盘证据。 |

## 3. 痛点优先级

| 痛点 | 证据强度 | MVP 是否覆盖 | 覆盖方式 |
|---|---:|---|---|
| 术语/专名错译 | 中 | 是 | 术语表、term hits、命中高亮。 |
| 字幕延迟 | 中低 | 部分 | 用 chunk 和状态标记表达准实时，不追求极低延迟。 |
| 字幕不稳定 | 中低 | 是 | partial/final 状态，final 固定入时间轴。 |
| 前文错误无法回修 | 低但差异化强 | P2 可选 | 可解释回修 demo，伪数据，非主链路。 |
| 会后难复盘 | 中高 | 是 | 导出 Markdown/JSON。 |
| 网课/技术分享不适配 | 中 | 是 | 技术术语表、固定技术分享样例、双语时间轴。 |

优先级解释：

- P0 优先覆盖“证据较强或能形成可验证闭环”的能力：术语约束、partial/final 状态、会后复盘、Markdown/JSON 导出。
- 字幕延迟和视觉稳定性只做状态表达，不在 MVP 中追求专业实时同传指标。
- 前文自动回修属于差异化假设，只允许 P2 伪数据 demo，不把它包装成已验证刚需。
- 网课/技术分享场景可作为 MVP 主场景，但中文强用户证据不足，演示叙事应写成机会方向而非普遍市场结论。

## 4. MoSCoW 范围

### Must

- 固定英文技术分享输入或模拟流。
- 术语表/热词导入，至少 8 个术语。
- 模拟 ASR 事件流，展示 partial/final。
- final 英文句子生成中文译文。
- 术语命中和高亮/标注。
- 双语时间轴，包含时间、英文、中文、术语命中。
- Markdown/JSON 导出，失败时提供页面可复制文本。
- 降级边界可见：ASR/翻译/导出失败时不阻塞 demo。

### Should

- UI 显示 timeline。
- UI 显示术语命中统计。
- 支持导出预览和文件下载。
- 支持低置信度标记。
- 支持 mock/real adapter 切换。

### Could

- 术语表 CSV 导入。
- 真实 ASR 接入，P0 未稳定前不得启动，不阻塞交付。
- 浏览器录音，P0 未稳定前不得启动，不阻塞交付。
- 简单播放器同步高亮。

### Won't

- 大型会议平台能力。
- 多人协作。
- 实时配音。
- 商业同传质量承诺。
- 用户账号和云端权限系统。
- 自动采集隐私音频。
- 完整实时自动回修系统。
- 多平台会议插件全接入。
- 大规模多语种评测。
- 复杂个人知识库或完整课程学习系统。

## 5. 最小闭环

```text
Demo audio
  -> mock ASR segments
  -> term-aware translation
  -> term hit timeline
  -> bilingual review artifact
  -> markdown/json export
  -> test/log/trace proof
```

关键是这条链必须端到端可运行。真实 ASR 和漂亮 UI 都是加分，不应阻塞闭环。

P0 最小纵切流程：

1. 准备一段固定英文技术分享音频或模拟流，内容包含 8-12 句技术术语。
2. 启动技术分享模式，加载术语表，例如 `RAG`、`vector database`、`embedding`、`API`。
3. 点击开始，系统按时间片输出 ASR 文本，并显示 partial/final 状态。
4. final 句子进入翻译流程，应用术语表约束。
5. 实时字幕视图展示英文、中文、术语高亮和状态。
6. 每句 final 写入双语时间轴。
7. Demo 结束后导出 Markdown/JSON 双语 transcript。
8. 检查导出内容包含时间、原文、译文、术语命中。

## 6. MVP 交付物

| 交付物 | 内容 | 验证 |
|---|---|---|
| Sample input | 样例音频或模拟转写 | 可重复运行。 |
| Object contract | `SampleStream`、`ASREvent`、`TermEntry`、`TermHit`、`TimelineItem`、`ExportArtifact` | 人工验收或最小测试。 |
| Event log | partial/final、translation、term_hit、export、fallback 事件 | 事件可追踪。 |
| Export file | Markdown/JSON 复盘 | 人工可读。 |
| Trace | 每个步骤的事件记录 | trace 文件或日志。 |
| Demo script | 3 分钟演示步骤 | 从 clean run 复现。 |

### 7.2 P0 关键路径

1. 冻结 P0 范围。
2. 准备固定英文技术分享样例和术语表。
3. 播放模拟 ASR partial/final 事件流。

5. 应用术语表并高亮命中。
6. 写入双语时间轴。
7. 导出 Markdown/JSON transcript。
8. 按 demo 脚本完整跑一遍。

## 8. MVP 成功标准

| 标准 | 验收口径 |
|---|---|
| 主链路可运行 | 一条命令或一组固定步骤可生成复盘文件。 |
| 有 AI-native 特征 | 至少有术语约束、结构化翻译、术语命中和 trace。 |
| 不是聊天壳 | 有显式数据对象、工具接口、导出 artifact。 |
| 可解释 | 术语命中和降级记录包含 reason/status。 |
| 可复盘 | Markdown 输出能被用户直接阅读。 |
| 可验证 | 实现阶段通过 pytest 或最小脚本验证，demo script 可复现。 |
